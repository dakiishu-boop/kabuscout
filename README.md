# KabuScout — 日本株 全銘柄スクリーニング＋自己学習アシスタント

東証（プライム・スタンダード・グロース）の全銘柄を毎日引け後に走査し、押し目などのシグナルを拾い、
**過去の結果から学習したAIで「勝ちやすい順」に並べて**スマホやPCに通知します。

## 仕組み

```
JPX銘柄一覧 ─┐
Yahoo Finance ┴→ 株価25年分(Parquet) → 指標 → 9つの検出ルール → AIスコア → 通知 / Webページ / ペーパートレード
                                                      ↑                 │
                                                      └── 答え合わせ・再学習 ←┘
```

| 検出ルール | 内容 |
|---|---|
| 押し目(25日線) | 上昇トレンド中、出来高を細らせながら25日線まで調整し反転の兆し |
| 深押し(75日線) | 長期上昇トレンドの銘柄が75日線まで押して反発 |
| 52週高値ブレイク / ボックス上抜け | 出来高を伴う上放れ |
| 出来高急増(初動) | 高値から離れた放置銘柄に3倍超の出来高 ← 見落とされがち |
| 地合い逆行の押し目 | 市場が下げる中で踏みとどまる強い銘柄 ← 見落とされがち |
| スクイーズ | 値幅が半年で最小まで収縮、上放れ待ち |
| ゴールデンクロス / 売られすぎ反発 | 定番 |

### 自己学習（放っておくほど賢くなる）
1. 過去約25年の全営業日でシグナルを再現し、「翌日寄付きで買ったら、10営業日以内に +2ATR(利確) と −1ATR(損切) のどちらに先に届いたか」を正解ラベルにする
2. トレンド・出来高・ローソク足・相対強度など約50の特徴量から、勾配ブースティングで勝ちやすさを学習（新しいデータほど重視）。
   地合い系の特徴量は特定時期の丸暗記を招いたため、銘柄スコアからは外している
3. 5営業日ごとに再学習。複数の候補モデルを「学習に使っていない直近期間」で比較し、さらに**現役モデルと両者にとって未知の期間で対決させ、勝った方だけ採用**
4. 戦略ごとの直近120日の成績から重みを自動調整（今の相場で効いている網を重く）
5. 実際に通知した候補は10営業日後に自動で答え合わせされ、ダッシュボードで成績を追える

新しい検出ルールは `kabuscout/strategies.py` に関数を1つ足すだけで、次の再学習から自動的に評価・活用されます。

## 待たずに学習を回す仕組み
- **約25年分（2002年〜）の株価**で学習・検証（Parquet 保存で約180MB）
- **研究ループ**（毎週土曜に自動実行）: 戦略の条件（押し目の深さ・出来高の倍率など）を過去データで何百通りも試し、
  次の安全装置をすべて通ったものだけ採用する
  1. **金庫**: 直近120営業日は研究中に一切見ず、最後に1回だけ確認。開けた回数が増えるほど合格ラインを上げる
  2. **年ごとの安定性**: 全期間平均ではなく「平常時の年ごとの成績の中央値」で比較し、プラスの年の割合が下がる条件は不採用
  3. **多重検定の補正**: 試した条件の累計数が多いほど厳しい有意水準を課す（Bonferroni補正）
  4. **取引コスト**: 1往復0.2%を差し引いて評価
- **売買ルールの研究**: 利確（ATRの1〜8倍）・損切（0.75〜3倍）・最長保有日数（5〜60日）の280通りも同じ安全装置で比較。
  保有日数が違うと1回あたりの損益は比べられないので「損益合計 ÷ 保有日数合計 × 250（1枠あたりの年率換算）」で評価。
  採用されると、ラベル付け・AIの学習・ペーパートレード・通知の利確/損切目安がすべて新ルールに切り替わる
- **過去でのペーパートレード**: 1年ずつ「その年より前のデータだけで学習したAI」で売買（ウォークフォワード）。
  同じシグナルからランダムに選んだ場合・日経平均を持ち続けた場合と比較してWebページに表示

## 危機局面は「特例」として扱う
リーマン・ショック、東日本大震災、コロナ・ショック、令和のブラックマンデーなど14の危機を出来事カレンダー（`kabuscout/regimes.py`）に登録し、
さらに日経平均の変動率・下落率から**未知の急変も自動検知**する。特例期間のデータは
- 学習では捨てずに重みを30%に下げる（極端な値動きを「よくあるパターン」と覚えないように）
- 評価・研究ループでは平常時と分けて採点し、危機時に大きく悪化する条件は採用しない
- 本番で特例局面に入ったら通知とWebページに警告を出し、ペーパートレードの新規買いを1銘柄に絞る

市場区分再編・PBR改善要請・新NISA・マイナス金利解除などの制度変化も記録し、時代区分ごとに戦略の成績を比較できる。

## 現時点の実力（2026-10、25年分で検証）
- 値動きだけのシグナルは、**取引コスト（0.2%/往復）を引くとどの戦略も平均ではマイナス**（コスト控除前はほぼ損益ゼロ）
- 売買ルールを見ると、現行（+2ATR/−1ATR/10日）は頻繁に売買しすぎてコスト負けが大きく（1枠あたり年率 −14%）、利確を広く・保有を長くするとほぼ損益ゼロ（+2%）まで改善する。ただし直近半年の金庫期間ではわずかに現行に負けたため未採用
- それでもAIの銘柄選びには効果があり、過去でのペーパートレードは年率 **AI +1.7% ／ ランダム選定 −10.9%**
- ただし**日経平均を持ち続けた場合（+8.2%）には及ばない**。研究ループも「偶然の範囲を超える改善」はまだ見つけていない
- 大きく伸ばすには新しい情報源が必要（最有力は J-Quants の決算・信用残・投資部門別売買データ）
- 注意: 対象は現存銘柄のみ（倒産・上場廃止銘柄が入らない生存者バイアス）、戦略条件は過去を見て作っているため、過去の成績は実際より良く見えやすい

## セットアップ

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dashboard.txt   # ダッシュボード不要なら requirements.txt
.venv/bin/python -m kabuscout daily      # 初回は全銘柄の履歴取得＋初期学習（10分前後）
.venv/bin/streamlit run dashboard.py      # ダッシュボード
```

### 通知
`.env.example` を `.env` にコピーして設定（どちらか片方でOK）:
- **Discord**（おすすめ・カード形式で見やすい）: サーバーの「チャンネルの編集 → 連携サービス → ウェブフック」で URL を作成 → `DISCORD_WEBHOOK_URL`
- **ntfy**（無料・登録不要）: スマホに ntfy アプリを入れ、推測されにくいトピック名を購読 → `NTFY_TOPIC` に同じ名前

`.venv/bin/python -m kabuscout notify-test` で確認。Mac の通知センターにも出ます。

## 自動実行

### A. Mac で動かす（簡単）
```bash
bash scripts/install_launchd.sh
```
平日16:30に実行。**スリープ中だった場合は次に開いたときに自動で実行**され、翌朝7:30にも保険の枠があります（処理済みの日はスキップ）。
電源オフ中は動きません。※ 書類・デスクトップ フォルダ内に置くと macOS の権限で失敗することがあるので、`~/kabuscout` などに置いてください。

### B. GitHub Actions で動かす（PCを閉じていてもOK・無料）
1. このフォルダを GitHub の **public** リポジトリに push（無料プランで GitHub Pages を使うため）
2. Settings → Secrets and variables → Actions に `NTFY_TOPIC` か `DISCORD_WEBHOOK_URL` を登録
3. Settings → Pages の Source を「GitHub Actions」にする
4. Actions タブで `daily-screening` を手動実行（初回は全履歴取得で20分程度）

以後、平日15:45に起動し、Yahooのデータが確定する15:55頃まで待ってから実行、通知とWebページ更新が行われます（GitHubの混雑で遅れることがあります）。学習状態はキャッシュで引き継がれます。
結果は Web ページ（https://dakiishu-boop.github.io/kabuscout/）でも見られます。A と B を両方動かすと通知が二重になるのでどちらかに。

## データソースと拡張候補

| 用途 | 現在 | 拡張候補 |
|---|---|---|
| 銘柄一覧・業種 | JPX 東証上場銘柄一覧（無料） | — |
| 日足 | Yahoo Finance / yfinance（無料・非公式） | **J-Quants API**（JPX公式。無料プランは遅延データ、有料プランで最新の株価・財務・決算予定） |
| 決算予定 | Yahoo Finance（上位候補のみ） | J-Quants / TDnet |
| 財務 | — | EDINET API（金融庁・無料・要APIキー） |
| 発注 | ペーパートレードのみ | kabuステーションAPI（三菱UFJ eスマート証券）、立花証券 e支店 API |

## 自動売買について
現段階は**ペーパートレード**（推奨どおり機械的に売買したらどうなるかの記録）まで。
数ヶ月分の実績で期待値がプラスに安定することを確認してから、証券会社APIの発注モジュールを追加するのが安全です。

※ 本ツールの出力は投資助言ではありません。売買の判断はご自身で行ってください。
