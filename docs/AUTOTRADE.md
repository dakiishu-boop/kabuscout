# 自動売買（autotrade）

kabuscout のデータ（株価25年分・決算・適時開示）を使う、**全自動の売買システム**です。
証券口座が無い間は**仮想の口座（ペーパートレード）**で毎日動き、口座ができたら注文の窓口だけを差し替えます。

※ 投資助言ではありません。過去の検証の成績は将来の成績を約束しません。

### 成績が「データの偏り」や「運」でないかの確認

| 確認 | 年率 2008〜 | 年率 2019〜 | 最大下落 |
|---|---|---|---|
| そのまま | +24.8% | +18.7% | −31.8% |
| 同じ仕組みで銘柄だけランダム（3回） | −2.4〜−4.8% | −2.0〜−6.5% | −68〜−70% |
| 対象銘柄を全部同じ金額ずつ（母集団そのもの） | +5.2% | +6.1% | −48.5% |
| 倒産を混ぜる（上場企業の倒産率の6倍、10回） | 平均 +23.9%・最悪 +18.4% | − | 最悪 −44.0% |
| 約定が1日遅れる（判断の翌々日の寄付） | +13.8% | +9.1% | −38.3% |
| コスト 往復0.3% | +21.4% | +16.3% | −32.7% |
| コスト 往復0.5% | +13.5% | +10.4% | −34.8% |
| 配当を受け取る（税引き後） | +25.9% | +20.5% | −31.3% |
| 資金300万円 | +27.3% | +19.2% | −33.9% |
| 地合いで減らさない（常に5銘柄） | +30.1% | +26.3% | −49.1% |

- ランダムに選ぶと負ける＝成績は「AIの銘柄の選び方」から来ている。母集団（現在上場の銘柄だけ＝生存者バイアスあり）そのものの上げ幅は年+5%程度
- kabuscout の同じコストの成績（0.3%: +6.1%、0.5%: +4.0%）と比べても、どのコストでも上回る
- 効いている特徴量（単独の予測力の大きい順）: 固有の値動きの小ささ・変動率の小ささ・配当利回りの高さ・急騰の少なさ（低ボラティリティ効果）、
  52週安値からの距離、売買の厚さ（流動性）、業績の上方修正からの経過日数。どれも2008〜2018年と2019年以降で同じ向き

### 決め方（後から都合よく選ばないための約束）と、割り引いて読むべき点

- 売買の形（銘柄数・入れ替えの間隔・持ち続ける範囲・地合い）とAIの設定は、**2008〜2018年（設計期間）のシャープ比だけ**で選んだ。
  2019年以降は「選んだ後の確認」。ただし約70通りを試し、その間に2019年以降の数字も目にしているので、その分は良く見えている可能性がある
- **AIの「くじ運」が大きい**: 学習に使う日の間引き方を変えただけで、1つのモデルの年率は +15〜+24% とぶれた（8銘柄の形）。
  そのため本番は3つのモデルの平均にした（上の表はその平均の結果）。それでも年ごとの成績は運で大きく動く。数年単位で判断する
- **生存者バイアス**: 株価は今上場している銘柄だけ（kabuscout と同じ）。上の「倒産を混ぜる」は仮定の確率での検証で、実際の上場廃止銘柄のデータでは確かめていない。
  倒産率は2008〜2010年は kabuscout のジャーナル §49 の値、それ以外の年は資料を確かめずに「年5社」と多めに仮定した
- 2018年10月より前は1,000株単位の銘柄が多く、100株で計算した2008〜2018年の結果は実際より良く見えやすい（kabuscout と同じ注意。だから2019年以降も並べている）
- 株価の異常値の除去（kabuscout の clean_panel）は前後3日の中央値を使うので、過去の検証にはわずかな先読みが入る（kabuscout と共通。影響は小さいと考えるが測っていない）
- 寄付の約定は始値ちょうど＋片道0.1%と仮定。寄付の気配が飛ぶ小型株では、実際はもっと不利になりうる（0.5% でも上回ることは確認済み）
- **最悪の年は kabuscout より悪い**（2022年 −22%、2011年 −16%、2008年 −14%）。常に全力で持つと最大下落 −49% なので、
  日経平均が75日線を下回ったら持つ数を半分にする安全策を入れている（それでも1年で2割下がる年はある）

## 儲けは本物か（追加の検証・2026-11-26。本番のデータ・上の表と同じ形）

| 確認 | 年率 2008〜 | 年率 2019〜 | 最大下落 | 読み方 |
|---|---|---|---|---|
| そのまま | +24.8% | +18.7% | −31.8% | 基準 |
| 売買が成立しない日（出来高0・高値=安値）は約定しない | +25.4% | +18.9% | −30.7% | 影響なし |
| 2018年10月より前は**全銘柄1,000株単位** | +12.7% | +16.0% | −29.2% | 下限の見積もり。2008〜18年は資金の26%しか使えない |
| 株価の異常値の除去を**過去の値だけ**で（モデル1つ同士で比較） | +25.2%（元 +27.3%） | +21.1%（元 +29.2%） | −34.2% | 2019年以降は8ポイント低いが、モデル1つの運の幅（+11〜+29%）の中 |
| 単純な並べ替え（値動きの小ささ・配当利回りだけ） | +1.5〜+2.9% | −0.7〜+5.3% | −32〜−37% | AIの組み合わせ方が利益のほとんどを生んでいる |
| **実際の上場廃止銘柄**を混ぜる（2025-01〜2026-07） | +13.2%（混ぜない +13.6%） | − | −14.2% | 影響なし |

- **取引の点検**（2,196回）: 分割をまたいだ・出来高0・張り付きなどの「データの誤りかもしれない」取引は40回で、損益への寄与は**マイナス**（−5.9%）。
  分割をまたいだ17回の平均は −3.9%（全体 +1.15%）＝分割の調整漏れで儲けが水増しされている形跡は無い。大勝ちの上位20回にはどれも印が付かなかった
- **上場廃止銘柄**: J-Quants の上場廃止262社（2024-07〜2026-07に一覧から消えた会社）のうち、Yahoo に無い261社を足した。
  1年分の履歴があって対象になりうるのは162社。AIの上位30位に入ったのは31社で、ほとんどが TOB・MBO（買付価格で値段が止まる）。
  実際に買ったのは11社・損益はほぼ0。**ただし対象は約1.5年分だけ**で、倒産が多かった2008〜2009年のような時期は確かめられていない
- **kabuscout との差は偶然か**（週ごとの損益の差の t。kabuscout の週ごとの資産は backtest.json の curve.ai）:
  全期間 t=3.45、2008〜2018年 t=2.95、**2019年以降 t=1.82**（年ごとの差では t=1.46）。
  → 全期間では偶然とは考えにくいが、**選んだ後の検証期間（2019年〜）だけでは、kabuscout より上と言い切れる水準（t≥2.5）に届いていない**
- 2つの週ごとの損益の相関は +0.47。半分ずつ持つと 年率 +17.0%・最大下落 −26.9%（片方だけより下落が浅い）
- **約定の遅れに弱い**: 判断の翌々日に約定すると 2019年以降の年率は +18.7% → +9.1%（半分）。毎日の実行が遅れた・飛んだ日はこれと同じことが起きる。
  運用上の大事な危険（GitHub の定時実行は遅れることがある。kabuscout の daily-screening には予備の起動時刻がある）

## 改善の採用ルール（試す前に決めたもの・2026-11-26）

新しい案は、次を**すべて**満たしたときだけ採用する（満たさなければ「改善なし」と記録し、良さそうな案でも出さない）:
1. 2008〜2018年・2019年以降の**両方**で、凍結した版よりシャープ比が高い（または最大下落が同程度で年率が高い）
2. 学習に使う日の間引き方3通りの**どれでも**凍結した版を上回る
3. 凍結した版との週ごとの損益の差の t ≥ 2.5（kabuscout の min_t_model と同じ水準）
4. 「投資する量を増やしただけ」（地合いで減らすのをやめる等）は改善に数えない（ジャーナル §82 と同じ）

### 改善の探索の結果と、追加の確認の条件（2026-11-26）

- 13通りの案（入れ替えを1〜3日ごと・予測期間2〜3日・その平均・特徴量を間引いたモデル）を上のルールで判定し、通ったのは
  **「毎日入れ替え・50位以内は持ち続ける」だけ**（t=2.52。13通りの中で偶然1つ通る確率を考えると、t≈2.9 欲しいところでぎりぎり）
- そこで、採用の前に**凍結した版と同じ条件で並べた確認**を行う（このルールは試す前に追加したもの）:
  コスト0.3%・0.5%、約定が1日遅れる、売買不成立の日は約定しない、2018年10月より前は1,000株単位、
  口座を300万円・1,000万円で頭打ちにする（超えた分は毎年末に引き出す。成績は口座そのものの損益率をつないだもの）、
  1注文を20日平均売買代金の3%まで、口座300万円＋コスト0.5%＋売買不成立の日は約定しない
- **すべての条件で、2019年以降のシャープ比か年率のどちらかが候補の方が高いときだけ採用**する。1つでも負ければ凍結した版のまま

## kabuscout との違い

| | kabuscout（スクリーニング） | autotrade（自動売買） |
|---|---|---|
| 見る銘柄 | 9つの検出ルールに当てはまった銘柄だけ | 流動性の条件を満たす**全銘柄**（毎日 約1,500〜2,500銘柄） |
| AIが当てるもの | 「+2ATR に −1ATR より先に届くか」 | 「5営業日後に**他の銘柄より**上がっているか」（その日の中での順位） |
| 売買 | 利確・損切・期限で1銘柄ずつ手仕舞い | **5営業日ごとに入れ替え**（上位5銘柄）。順位が30位以内なら持ち続ける（売買の回数を抑える）。弱い相場では2銘柄に減らす |
| 資金の使い方 | 平均で約6割（買える候補が少ない日が多い） | 平均で約7割 |
| 注文 | 人が通知を見て発注 | 毎日自動で翌朝の注文を作り、安全装置を通して出す |

## 仕組み

```
kabuscout の毎日の実行（株価・決算・適時開示の更新）
   ↓
autotrade daily（毎営業日の引け後・GitHub Actions）
   1. 前回の続きの営業日から1日ずつ: 分割の反映 → 前日の注文を「今日の寄付」で約定 → 終値で時価評価
   2. 入れ替え日なら、全銘柄の特徴量（39個）→ AI（3つのモデルの平均）の点数 → 順位
   3. strategy.decide: 翌朝の寄付の成行注文を作る（バックテストと同じ関数）
   4. risk.RiskGuard: 安全装置を通った注文だけを出す
   5. 状態を data/autotrade/state.json に保存（毎日のバックアップにも入る）、Discord に通知
```

| ファイル | 役割 |
|---|---|
| `autotrade/features.py` | 特徴量（値動きの大きさ・配当利回り・騰落・移動平均・出来高・決算の反応・適時開示など39個）。毎日の順位（0〜1）にして使う |
| `autotrade/model.py` | AI（勾配ブースティング）。1年ずつ「その年より前のデータだけ」で学ぶウォークフォワード |
| `autotrade/strategy.py` | 売買の判断（入れ替え・持ち続ける範囲・弱い相場で減らす） |
| `autotrade/broker.py` | 口座（現金・株数・約定）。100株単位・実際の株価・寄付の約定・片道コスト・分割 |
| `autotrade/risk.py` | 注文直前の安全装置 |
| `autotrade/sim.py` | 過去での自動売買（毎日の運用と同じ broker と strategy を使う） |
| `autotrade/live.py` | 毎日の運用 |
| `autotrade/research.py` | 研究（kabuscout と同じ口座の前提で比べる） |
| `autotrade/brokers/kabusapi.py` | 実口座の窓口の雛形（**未検証・既定では発注しない**） |
| `autotrade/config.yaml` | 設定 |

## 安全装置（人が見ていなくても事故にならないように）

- データが古い（最新の株価が3営業日より前）→ その日の注文を全部止める
- 1注文の金額が40万円超、または資金の35%超 → 止める
- 判断に使った値段が前日の終値から30%以上離れている（データの誤り・分割の調整漏れの疑い）→ 止める
- 1日の注文数が20を超える → 止める
- 口座が最高値から35%下がった → **新規の買いを止める**（売りは通す）。人が `data/autotrade/state.json` の `guard.halted` を `false` にするまで止まったまま
- JPX の監理・整理銘柄・上場廃止予定の銘柄は買わない。持っていれば翌朝売る
- 実口座の窓口は、環境変数 `AUTOTRADE_LIVE=1` と `dry_run=False` の両方がそろわない限り注文を送らない
- 毎日の実行の中では `continue-on-error`・30分の時間制限つき。自動売買が失敗しても kabuscout の本番（通知・キャッシュ・Web）は止まらない

## 使い方

```bash
python -m autotrade daily      # 毎日（GitHub Actions の daily-screening に組み込み済み）
python -m autotrade train      # AI を全期間で学び直す（daily の中でも8日ごとに自動で行う）
python -m autotrade status     # 最新のレポート
```

証券口座ができたら: 1) 検証用の環境（kabuステーションの検証用ポート）で `brokers/kabusapi.py` の項目を公式の資料で確かめる
→ 2) dry-run で数週間、ペーパートレードと同じ注文が作られるか確かめる → 3) 少額から。

## 研究の手順（再現のしかた）

作業ブランチに push すると `.github/workflows/autotrade-lab.yml` が動き、本番のデータのキャッシュを**読むだけ**で研究を実行して、結果をログに出す
（キャッシュは保存しない＝本番のキャッシュを押し出さない。Discord・Web・バックアップには触らない）。実行する内容は `autotrade/LAB_CMD`。

| 研究の段階 | `LAB_CMD` | 何を見たか |
|---|---|---|
| 1 | `research --horizons 5,20` | 5日・20日・両方の平均 × 12通りの売買の形 |
| 2 | `research --horizons 5 --suite v2` | 特徴量ごとの予測力・ランダム・母集団・倒産・地合い・損切・コスト・配当 |
| 3 | `research --horizons 5 --suite v3 --offsets 0,1,2` | 採用候補（8銘柄）の頑健性（間引き方・1日遅れ・資金） |
| 4 | `research --horizons 5 --suite v4 [--chosen ...]` | 3つのモデルの平均での最終確認（8銘柄・5銘柄） |

毎日の運用の所要時間（本番のデータ、GitHub Actions）: 学び直しのある日 約8分、ない日 約2分。

## これから

1. **本番の毎日の実行に入れる**: このブランチを main に取り込むと、daily-screening の中で毎営業日に自動で動き始める（Discord にも届く）
2. **数ヶ月の前向きの記録**で、過去の検証どおりか（1回あたりの平均・勝率・順位の当たり具合）を確かめる。kabuscout の口座と並べて比べる
3. 証券口座ができたら、kabuステーションAPI（または立花証券 e支店API）の窓口を公式の資料で確かめ、dry-run → 少額の順に進める
