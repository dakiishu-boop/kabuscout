# USScout — 米国株版（月1回の組み直し＋自動売買のひな形）

日本株版（KabuScout）とは別の仕組みです。日本株の毎日の実行・ペーパートレード・設定には影響しません。
研究の記録と数字の出どころは [docs/JOURNAL.md §90](JOURNAL.md)。

## 先に結論（2008〜2026年の検証、資金6,700ドル＝100万円・1株単位・配当込み）

| 選択肢 | 年率（ドル） | 最大下落 | 税引き後 | 円建て |
|---|---|---|---|---|
| **S&P500（SPY）を持ち続ける**（自動売買の既定） | **+10.8%** | −51% | +10.8%（NISA） | +13.0% |
| SPY＋10か月平均の逃避（下げ相場は米ドルMMF） | +7.4% | **−27%** | +5.9%（特定口座） | +9.5% |
| S&P500 個別株モメンタム上位10 | +4.7% | −52% | +3.5% | +6.8% |
| ETFローテーション（上位3本） | +4.4% | −33% | +3.4% | +6.5% |
| （参考）日本株版の過去ペーパートレード（README） | +8〜11% | −30〜−40% | | |

- **売買する戦略で、手数料（片道0.495%）と税金の後に S&P500 を持ち続けるより年率が高いものは無かった**。米国の大型株は参加者が多く、値動きの癖が小さい（§57 の短期売買も同じ結論）
- S&P500 を持ち続けるだけで、日本株版と同じかそれ以上の年率（ただし最大下落 −51%、円建て −56%）
- 年率を上げる仕組みとして根拠があるのは「S&P500 を NISA で持ち続ける」＋「日本株のAIを特定口座で」の組み合わせ（§61: 2016〜2026年・円建て・税引き後で、
  S&P500 30%＋AI 70% は +12.3%・最大下落 −18%、50:50 は +14.0%・−20%、AIだけは +9.7%・−22%）
- NASDAQ100（QQQ）を持ち続けると +15.2% だが、**QQQ を選んだのはこの期間に良かったのを知った後（後知恵）**。将来も同じとは限らない
- 注意: 上場廃止の会社の株価は無料では取れない（生存者バイアス）ので、個別株の成績は実際より甘い可能性がある。それでも SPY に届かなかった

## 年利益を上げる仕組み: 日本株のAI＋S&P500（NISA）の組み合わせ（`python -m usscout combo`）

日本株版の過去ペーパートレード（kabuscout の `data/backtest.json`）と、米国版の S&P500 の口座を、円建て・税引き後で合わせた結果
（2008-01〜2026-11、毎年初めに分け方を戻す。コスト・為替の手数料・税金込み。表の全体は [docs/us_combo.md](us_combo.md)）:

| 分け方 | 年率（税引き前） | 税引き後 | 最大下落 | 最悪の年 |
|---|---|---|---|---|
| 日本株のAIだけ（今のやり方） | +8.8% | +7.0% | −38% | −17% |
| AI 70%＋S&P500 30% | +10.7% | +9.4% | −30% | **−9%** |
| **AI 50%＋S&P500 50%**（usscout.yaml の combo.us_share の既定） | **+11.7%** | **+10.8%** | **−29%** | −13% |
| AI 30%＋S&P500 70% | +12.5% | +11.9% | −38% | −27% |
| S&P500 だけ | +13.0% | +13.0% | −54% | −47% |

- 30%・50% は、日本株のAIだけより**年率・税引き後・最大下落・最悪の年がすべて良い**（日本株のAIは日本の小型株・下げ相場に強く、S&P500 と動きが違う）
- S&P500 を NISA でなく特定口座で持った場合（毎年、含み益にも課税する厳しめの計算）: 50% で税引き後 +9.3%（NISA なら +10.8%、AIだけ +7.0%）。
  税引き前の年率（+11.7%）は口座に関係なく同じ。NISA の分の上乗せは約1.5ポイント
- **S&P500 の側は、日本の証券会社の NISA（成長投資枠）で S&P500 の投資信託・ETF を買って持つ想定**。usscout の自動売買（ペーパー口座・Alpaca）は NISA ではないので、
  この組み合わせの S&P500 の側には使わない。年に1回の分け方の戻しは `combo --jp-yen --us-usd` で出す金額を手で動かす
- 既定の 50% は提案です。2026-10-23 のあなたの判断（日本株は「AIのみ」で続ける）と違うので、日本株の本番の設定は変えていません
- 日本株のAIだけの値（+8.8%・−37.7%）は、日本株版が自分で出している過去ペーパートレードの値（+8.8%・−37.8%）と一致
- 年に1回、今の2つの口座の額から動かす金額を出す: `python -m usscout combo --jp-yen 700000 --us-usd 2000`（割合は `--share`）
- 注意: 2008〜2026年はドル円が 110円 → 159円と円安で、米国株の円建ての成績を押し上げている。NISA の今の制度は2024年からなので、それより前もあったと仮定している

## S&P500 を超えるアイデアの検証（§91・§92）: どちらも不合格

結果を見る前に基準を決めて commit してから試しました。基準は、長い期間（1929年〜）・研究が出た後の期間・米国以外の4つの指数のすべてで S&P500 を持ち続けるより良いこと。

| アイデア | 2008〜2026（SPY 配当込み） | 1929〜（配当なし） | 研究の後 | 米国以外4つ | 判定 |
|---|---|---|---|---|---|
| 上昇トレンドのときだけ2倍（Gayed & Bilello 2016） | +11.7%・−50%（S&P500 +10.8%・−52%） | +6.2%（+6.0%） | **+6.8%（+11.7%）** | **0/4** | 不合格 |
| 値動きが落ち着いているときほど多く（Moreira & Muir 2017） | +13.4%・−30% | **+3.3%・−98%（+6.0%）** | +13.5%（+12.4%）※ | **0/4** | 不合格 |

※ 同じ平均の投資比率で持ち続ける方が +15.7% と高い（出入りに意味が無い）。表の全体は [docs/us_levtrend.md](us_levtrend.md)・[docs/us_volmanaged.md](us_volmanaged.md)

- 2008〜2026年だけ見ると良く見えるが、長い期間・他の市場で再現しない。米国の長い上げ相場でしか効いていない
- 2倍の商品は NISA の成長投資枠の対象外（特定口座で毎年課税）なので、S&P500 を NISA で持ち続けるのに比べて年2〜3ポイント不利
- **自動売買の既定は「S&P500 を持ち続ける」のまま**。2つは `--strategy lev_trend_spy` / `--strategy vol_managed_spy` で選べる
  「前向きのペーパー口座で見守る用」として入れてあります（usscout の口座のシミュレーション 2008〜2026: lev_trend_spy +11.7%・−48%、
  vol_managed_spy +15.2%・−33%（実際の SSO・寄付で約定・1株単位）。**この +15.2% は信用しないでください**: usscout の株価は2005年からなので、2008年の前の「長期の値動きの大きさ」を落ち着いた 2005〜07年だけで計算してしまい（年12.4%。1993年からなら16.9%）、暴落の前に投資比率を下げていた（2008年1〜8月の平均 0.53倍。長期の検証の作り方では 0.85倍）。偶然の当たりで、本番では再現しない。事前に決めた作り方の値は +13.4%。過去35か月の試し運転と過去の検証の差は 1.1〜1.4%）
- 使うなら（ペーパー口座）: `python -m usscout rebalance --strategy vol_managed_spy --execute` を毎月の最初の営業日に
- 東証の S&P500 2倍 ETF（2237 iFreeETF S&P500レバレッジ、2239 上場インデックスファンド S&P500先物レバレッジ2倍）は、SBI証券なら国内株の手数料が無料
  （インターネットコース・電子交付が条件）。ただし usscout は東証の ETF の株価・発注には対応していない（米国の SSO で計算）。円建て・為替の扱いは未確認

## 仕組み

```
Wikipedia（S&P500 の構成銘柄・入れ替えの履歴） ─┐
Yahoo Finance（2005年〜の日足・配当・分割）     ─┴→ 月末の引けで判定 → 目標の比率 → 注文 → 安全装置 → 証券会社（既定: 手元のペーパー口座）
                                                    └→ 過去の口座のシミュレーション（コスト・税金・円建て・金庫）
```

- 判定: 月の最後の営業日の引けまでのデータだけを使う（先読みなし。テストで確認）
- 売買: 次の営業日の寄付の成行（日本時間 23:30、夏時間 22:30）。日本の昼〜夜に注文を出せば間に合う
- 戦略は `usscout/strategies.py`。新しい戦略は `Strategy` を継承して `target()` を書き、`REGISTRY` に足すだけで backtest・screen・rebalance から使える

## 使い方

```bash
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m usscout fetch        # 銘柄表と株価（初回 約2分）
.venv/bin/python -m usscout backtest     # シミュレーション一式（約10分）→ data/us_scout/report.md
.venv/bin/python -m usscout screen       # 今月の目標の比率と理由（--strategy stock_mom で個別株の順位）
.venv/bin/python -m usscout rebalance    # 注文の案を表示するだけ
.venv/bin/python -m usscout rebalance --execute   # 手元のペーパー口座に注文（次の営業日の寄付で約定）
.venv/bin/python -m usscout status       # ペーパー口座の状況
```

パソコンを使わずに計算したいとき: GitHub の Actions タブ → `us-research` → Run workflow（手動の実行だけ。注文・通知はしない。
結果は実行ページの Artifacts に入る）。※ このボタンは `.github/workflows/us-research.yml` が main ブランチに入ってから出ます。
2026-11-26 に作業ブランチで1回実行し、全部の手順が成功、結果は手元の計算と一致しました（約6分）。

## 自動売買

- 既定は **手元のペーパー口座**（作り物のお金、`data/us_scout/paper_account.json`）。実際のお金は動きません
- 毎月の流れ: 月の最初の営業日（日本時間の朝〜夜）に `fetch` → `rebalance --execute`。翌月の実行のときに、前回の注文が寄付の値段で約定します
- **過去をたどる試し運転** `python -m usscout replay --start 2024-01-01`: 毎月の判定日に「その日までの株価」だけで `rebalance --execute` を実行し、
  ペーパー口座で約定させる（本物のペーパー口座とは別の場所）。2024-01〜2026-10 の35か月で、過去の検証（backtest）との差は
  S&P500 を持ち続ける 0.00%、SPY＋10か月平均 0.5%、ETFローテーション 2%（資金20万ドルなら全戦略で 0.2〜3%）。
  資金6,700ドルの個別株モメンタムは最大14%ずれる（1銘柄670ドルで、値段の高い株を何株買えるかが判定日の終値と寄付で変わり、10銘柄に集中しているので差が積み重なる）
- ペーパー口座は過去の検証と同じく「調整後の株数」で持つので、株式分割の後も評価額が続き、配当は同じ銘柄に再投資したとみなします
- 入金などで増えた現金は、資金の5%を超えたら月末の組み直しで買い足します（`backtest.rebalance_band`。小さいずれは売買しない）
- 証券会社をつなぐ窓口: `usscout/broker/`。`Broker` を継承して `account / positions / submit / cancel_all` を書けば、ほかの証券会社にも差し替えられる
  - `alpaca.py`: Alpaca（米国の証券会社）の REST API のひな形。**この開発環境からは接続できず、一度も動かしていません**。
    日本の居住者が口座を開けるかも確認していません。使うなら、まず Alpaca のペーパー口座で試してください。
    鍵は環境変数 `ALPACA_API_KEY_ID` / `ALPACA_API_SECRET_KEY`（`.env`。リポジトリには絶対に書かない）
  - 日本の証券会社（SBI・楽天など）の米国株には、一般向けの発注 API は確認できていません
- **実際のお金で発注する条件**: `usscout.yaml` の `trading.live: true` と、環境変数 `USSCOUT_LIVE=1` の**両方**。片方だけなら止まります
- 安全装置（`usscout.yaml` の trading）:
  - `data/us_scout/STOP` というファイルを置くと、すべての注文を止める（緊急停止）
  - 株価データが古い（4日より前）・売買の合計が資金の2.1倍超（全部の入れ替えで2倍）・1注文が資金の40%（または目標の比率）超・前日から50%以上動いた値段 → 止める
  - 口座が最高値から35%下がったら、新規の買いを止めて売りだけ出す
  - 同じ判定日の注文は1回だけ（やり直しは `--force`）
